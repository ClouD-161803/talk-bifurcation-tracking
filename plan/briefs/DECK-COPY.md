# Working on a copy of the deck

The deck `index.html` of the talk folder, `/Users/claudiovestini/git/talks/bifurcation-tracking`, is written by one agent at a time, and during your run another agent writes it. Hence you never write `index.html`, and you never run `npm run check` or `npm run pdf` in the talk folder, since both rewrite it. Work on a copy instead.

1. At the start, make two copies in the talk folder, with the tag given in your brief: `cp index.html index.<tag>.base.html` and `cp index.html index.<tag>.html`. The copies are in the talk folder so that the relative paths of the deck hold, and they are kept out of `git status` by `.git/info/exclude`.
2. Edit `index.<tag>.html` only. Where your brief says to embed a scene, pass the path of this copy to `tools/deck/embed_scene.py` in place of `index.html`.
3. Verify the copy live with `scripts/chrome.mjs` of the talk folder, whose `deckUrl(deck, query, hash)` takes the path of the copy. A probe that walks the slides, prints the chrome of the viewers, and writes a screenshot per slide is at `/private/tmp/claude-501/e2d/slides-probe.mjs`. Copy it, point it at your copy and at the slides of your brief, and write the screenshots under the folder named in your brief.
4. At the end, write the patch with `diff -u index.<tag>.base.html index.<tag>.html > plan/patches/<tag>.patch` (an exit code of 1 of `diff` says that the files differ, and it is not an error), leave both copies in place, and give the path of the patch in your report. I apply the patch to `index.html` once the file is free, and I delete the copies.

Read the deck with `awk 'length <= 3000' index.html`, since ten lines of it are the base64 of the viewers, and find a slide by its comment `<!-- N, title -->`. Read `plan/briefs/COMMON.md` for the rules of the talk, and `plan/thesis-style-guide.md` for the style of the maths and of the notes, which are a script of one "Step n:" paragraph per fragment. Do not stage or commit, and do not run `cd`.

When your brief changes the template, `/Users/claudiovestini/git/slides`, work in a worktree of it, made with `git -C /Users/claudiovestini/git/slides worktree add /Users/claudiovestini/.t3/worktrees/slides/<name> -b talk/<name> main`. Build there with `npm run build`, after `npm ci` when `node_modules` is missing, test with `node --test "test/*.test.mjs"`, and leave the branch unmerged, since I merge it. The deck copy must then load your build of the theme: run `sed -i '' 's#"theme/#"/Users/claudiovestini/.t3/worktrees/slides/<name>/theme/#g' index.<tag>.html` on your copy, verify, and run the reverse `sed` before you write the patch, so that the patch holds the relative paths. Check with `grep -c worktrees plan/patches/<tag>.patch` that the patch does not name the worktree.
