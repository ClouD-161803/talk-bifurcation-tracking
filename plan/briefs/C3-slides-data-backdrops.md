## The template today

A `div.backdrop` takes `data-scene="<name>"`, and `src/scenes.ts` computes the strands of each name in the browser (`SCENES`, `scene(name)`, the `Strand` type in `src/orbits.ts`: `pts` as a flat `Float64Array` of points, `times`, the period `T`, a `tone`, and an `alpha`). `src/orbits.ts` draws the strands on a base canvas and the moving heads with their trails on a head canvas (`class Orbits`, `heads()`), and `mount(root)` creates one `Orbits` per `.backdrop`. The tones are `orange`, `violet`, `text`, `hero`, and `line`, resolved from the theme's CSS variables in both the dark and the light mode. The tests run under `node --test` (`test/backdrops.test.mjs`, `test/orbits.test.mjs`, and the others), and `npm run check` runs them with the build and the lint. Read these files before you design anything.

## What to build

1. The capability. A `.backdrop` with `data-strands="<path>"` (the path relative to the deck's `index.html`) fetches the JSON on mount, turns its records into strands, fits their bounding box to the slide with the same margin and the same fill as `tubes`, and draws them with the engine of `src/orbits.ts`. A missing or malformed file leaves the backdrop empty and prints one console warning, and never throws. A `data-strands-select="<key>=<value>,..."` attribute (or a better name you justify) selects the records of a file, e.g. `family=7,frame=pulsating`, so that one file serves every backdrop of a deck. The `?still` parameter of the README draws these backdrops complete, as it does the others.
2. The format. Read the real file at `/Users/claudiovestini/git/talks/bifurcation-tracking/backdrops/broucke-families.json`, whose `"readme"` key documents it: records of `{"family": 7, "branch": "periapsis", "frame": "pulsating", "e": 0.12, "points": [[x, y], ...]}` for about twelve members per branch in the rotating-pulsating and the barycentric inertial frame, with the positions of the primary and the secondary per frame. Accept this layout as the format of the capability, document it in the README under "## Backdrops", and ship a small sample (a few members of two families, well under 200 kB) under `demo/` for the demo deck and the tests.
3. The color. Slide 2 of the talk needs many colors. Add to the strands a color keyed on the record, e.g. a hue per family and a lightness ramp along e, or a tone per branch, with the palette defined once in `theme/beeson.css` beside the existing tones so that it works in both modes. A `data-strands-color="<key>"` attribute (or your better name) picks the key. Keep the existing tones and scenes unchanged.
4. The heads. Render the `tubes` backdrop and one Broucke backdrop in three variants, heads as they are, heads at a quarter of their size, and no heads, in both modes, as screenshots under `/private/tmp/claude-501/<your folder>/heads/` and copied into your report folder in the worktree (`demo/compare/` or similar, not committed if large). Choose the variant that looks best, make it the default of the data-driven backdrops, keep the others selectable with an attribute, and say in the report why.
5. The backdrops of the talk. Build, in the demo deck of the template, one slide per backdrop the talk uses, so that Claudio can audition them: slide 2 (every branch of the three families, colorful, full-slide, in the frame or the pair of frames that fills a 16:9 slide best, with two or three candidate compositions), and the section backdrops family 7, family 8, and family 11 in the rotating-pulsating frame. Screenshot each candidate in both modes at 1920 by 1080 with `?still` and with the animation running, and list the files with their sizes in the report.
